Move the current jungle game into `v1/` unchanged and green, then build `v2/`: a real-time continuous 2D arena where heroes and monsters each have a small neural net (vision in, actions out), co-evolve by neuroevolution, and are replayed in a much richer, more detailed map and visual style. Branch `feat/v2-arena`, cut from `feat/jungle-sim`.

## Findings: InfiniClash inspection (read-only, nothing modified)
- Stack: TypeScript + PixiJS v8, Vite 8, Vitest 4, Jimp. Own ECS (src/core: world, entity, component, scheduler, spatial-hash, rng, fixed-step loop). About 2k lines in the parts relevant to us.
- Assets: NO tile art. Terrain is procedural: src/world/terrain.ts is a pure function of position (hashed value noise with smoothstep, "never repeats, fixed"), drawn by src/render/terrain-layer.ts (124 lines); obstacles in src/world/obstacles.ts (348) and src/render/obstacle-layer.ts (177); collision in src/sim/obstacle-collision.ts (167). The only art is character sprites: KayKit 3D low-poly models (Skeletons: Mage, Minion, Rogue, Warrior; Adventurers: Barbarian, Knight, Mage, Rogue, Rogue_Hooded) baked by scripts/bake (Blender-based, bake_sprites.py) into 8-direction sprite atlases (assets/atlas/Skeleton_*.png + .json, about 5 MB each, about 20 MB total, 95 animations per rig). The baked atlases and 51k baked frames are NOT in git (only assets/CREDITS.md is tracked); `npm run assets:fetch` clones the sources at pinned commits; atlas pack is `npm run assets:pack`. The 4 skeleton atlases exist on disk locally; adventurer atlases do not.
- Licence: KayKit packs are CC0 1.0 (LICENSE.txt in each pack, author Kay Lousberg). No attribution required, we record it anyway. No other third-party assets found. Terrain/obstacle code is the user's own.
- Combat code (src/combat, src/sim/ai.ts 324 lines, projectiles, obstacle-collision, movement): ECS, real-time, hand-written AI, damage, status effects, abilities. All hand-scripted; no learning. Useful as design reference (damage, cooldowns, dodge/status ideas) but it is a survival/horde game, not duel logic. We port ideas, not code.
- Reusable: (a) the 8-direction baked sprite atlases (CC0) as hero/monster art; (b) terrain.ts noise and the layer drawing as the base for a richer biome map; (c) obstacle-layer visuals; (d) bake/atlas scripts if more characters are wanted; (e) PixiJS renderer, camera and depth sorting for smooth replay.
- Forced consequence: InfiniClash's reusable pieces are TypeScript/Pixi, v1 is a single-file HTML canvas viewer served by a Rust binary. Using Pixi means v2 viewer gets a Node/Vite build step (the only dependency, viewer-side only). The Rust sim stays zero-dependency. Decision pending, see Open questions Q1 and Q3.
