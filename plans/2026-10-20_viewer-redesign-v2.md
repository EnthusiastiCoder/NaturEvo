## Library decision (research: research/viewer-ui-library-decision.md)
Options: (a) vanilla HTML/CSS/JS + CSS tokens + inline Lucide SVG sprite; (b) vanilla helpers (@floating-ui/dom 1.8.0, chart.js 4.5.1); (c) full shadcn/ui (React + Tailwind + Radix + Vite).
Recommendation: (a). Reasons: file:// blocks module scripts, so (c) needs an IIFE bundle + committed built CSS/JS, node_modules, a build step and ~140KB React for ~10 widgets; (b) adds vendored libs for 40 lines of CSS tooltip and two simple canvas/SVG charts. We copy shadcn's design language (zinc neutrals, border + muted-foreground, 0.5rem radius, 36px controls, card pattern) as plain CSS tokens and component classes. No build, no node_modules, `serve` unchanged. Lucide: `lucide`/`lucide-static` 1.60.0, ISC; copy needed SVG paths into ONE inline `<svg style="display:none">` sprite of `<symbol id="i-<name>" viewBox="0 0 24 24">` (stroke=currentColor, stroke-width 2, fill none, round caps/joins) with the ISC licence notice comment preserved; used via `<svg class="icon"><use href="#i-name"/></svg>`. If the implementer finds a real need for (c), STOP and ask; do not switch silently.

## Design system (one place)
- `:root` tokens: colours (--bg, --card, --card-2, --border, --fg, --muted, --accent (subtle jungle green), --good, --bad, --warn, --ring), spacing scale (--s1..--s6 = 4,8,12,16,24,32px), radii (--r-sm,--r-md=8px), font sizes (--fs-xs 12, --fs-sm 13, --fs-md 14, --fs-lg 18, --fs-kpi 28), --icon:16px, --control-h:32px, elevation (--shadow-pop). All CSS values outside `:root` use var(); no ad-hoc inline `style=` in markup (JS may set only dynamic widths/heights via style.width) and no hex colours outside `:root`.
- Documented component classes in viewer/STYLE.md (new file, short): `.btn` (+ `.btn-primary`, `.btn-outline`, `.btn-ghost`, `.btn-icon`), `.input`, `.label`, `.card` (+ `.card-title`), `.kpi`, `.tab`/`.tabs`, `.badge` (+ `.badge-good/.badge-bad`), `.tip` (tooltip), `.info` (info button), `.expander` (details/summary), `.table`, `.scroll` (bounded inner scroll).
- Info buttons and tooltips: `.info` is a `<button type="button" class="btn-icon info" aria-label="About <name>" aria-describedby="tip-<id>">` with Lucide `info` icon, followed by `<span role="tooltip" id="tip-<id>" class="tip">`. Shown on `:hover` AND `:focus-visible`/`:focus-within`, hidden otherwise, Escape hides; works by pure CSS + tiny JS for Escape. One `INFO` text map in JS (key -> text) generates them for KPIs, controls and each tuning knob (knob tooltip = description + "Range min to max, default d" built from /api/config min/max/default). Every icon-only button (play/pause, random seed, run, expand, close, reset) gets aria-label AND a tooltip (`title` is not enough alone).
- Icons (Lucide names): play, pause, dices (random seed), flask-conical or play (run), layers/bar-chart-3 (batch), sliders-horizontal (tuning), list (log), chevron-down/chevron-right (expanders), info, rotate-ccw (reset), trophy/skull (outcome), heart, coins, flask-round (potions), map-pin (zone), activity (replay), layout-dashboard (dashboard), x. No text glyphs/emoji as UI chrome: forbidden characters in markup/JS outside sprite-free text: emoji ranges, arrows and symbols (play/pause triangles, chevrons, check/cross marks, bullets) except the hero/monster/zone sprite arrays SP and ZN, whose emoji stay as placeholders.

## Screen design
Shell: v1 grid (100dvh, html/body overflow hidden, `grid-template-rows:auto minmax(0,1fr)`, all children min-height:0). Content max-width none.
1. Toolbar (one row, wraps below 900px): logo mark + "Jungle Sim"; segmented tabs (Replay = activity icon, Dashboard = layout-dashboard icon); right side only when served: Seed input (>=12ch), Run (btn-primary, icon), Random seed (btn-icon dices + tooltip), Batch popover (`details#batch-box`: runs input + Run batch), Tuning popover (`details#knob-box`, closed, grid of labeled knobs each with info button, bounded height, inner scroll, Reset knobs), `#run-status` as badge.
2. Dashboard tab (centerpiece, bird's-eye): row of KPI cards (Win rate big with badge, Avg deaths, Avg final level, Runs, plus Median final level and Boss-reached %, derived only from existing stats.js fields; if a field is not present omit the card, do not invent data) each with info button. Below: 2-column area filling the remaining height: left card "Final level distribution" chart readable when skewed: bin into <= 20 bars, y-axis with ticks, bar height linear by default with a "Log scale" toggle (checkbox styled input, default OFF unless max/median > 20 then ON), value label on hover/focus tooltip; right card compact table (level, runs, % of runs, cumulative %) in `.scroll` bounded panel; deaths distribution card only if stats.js has the data (else omitted). `#dstats` holds the KPI cards, `#hist` holds the chart (legacy ids kept).
3. Replay tab (inspector): top summary strip (always visible): `#summary` with `#outcome` badge (Won/Lost/In progress), `#sum-level`, `#sum-hp` (bar), `#sum-zone`, `#sum-progress`, deaths, gold, potions, each with Lucide icon + info button. Below: playback card (play/pause icon button, speed select, `#info`, `#scrub`), battle panel compact (small emoji sprites in a card), `#timeline` card filling remaining height (canvas sized to container on render and window resize, axis labels in token colours, no right gap). Drawer bar at bottom: `details#log-box` (Event log, `#log` inside, bounded overlay/panel max-height min(45vh,360px), inner scroll) and `details#more-box` (extra stats). All closed by default; opening one closes others; opening never grows the page.
Sizes: no page scroll (both axes) at 1920x1080, 1366x768, 1280x720 and 800x600, both tabs, loaded run, drawers closed and each open. <800px wide: toolbar wraps, battle stacks; at 800x600 still no page scroll. Below ~640x480 not guaranteed but no horizontal page scroll.
Cognitive load: default-visible inputs = Seed (served only), speed select, scrub, plus dashboard log-scale checkbox; everything else inside closed details.
