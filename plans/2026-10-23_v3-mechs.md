# v3 plan: big-robot duels with per-part combat (NaturEvo)

## Goal
Build v3/ (new branch `feat/v3-mechs`, cut from `feat/v2-arena`; v1/ and v2/ untouched and green) : a zero-dependency Rust sim where two giant humanoid robots, each with a physical sword (right) and shield (left), fight in a side-view arena. Neural controllers are evolved. Fighters must visibly attack AND defend: dodge, shield, deflect with the sword. Each move depends on named body parts; damaged or destroyed parts degrade or remove moves. Hits have a location, direction and impact that drive damage, knockback, hit-stop, sparks. Viewer: PixiJS + Vite, vector-drawn crisp robots, record mode, landing page with run picker and aggregate results.
Phase 1 (vertical slice, ships first): one robot design, 1v1 arena duel, defence working and visible, training, viewer, landing. Phase 2: arena cut from the map tile, map + campaign integration.

"Hit sparks and weapon clash effects, Impact reaction by hit point and direction, ... zone damage multipliers or ... tankiness of a part depends on it's health". "if hero has a sword, he actually uses the sword to defend against attacks"; "realistic hitboxes, actual impact on where the hit lands". "the arena should match the surroundings".
Project rules (CLAUDE.md): plan in plans/; new branch `feat/v3-mechs` from `feat/v2-arena` (never commit to main); tests first (failing) via test-writer; one file per commit, small granular commits, `git add` and `git commit` run as separate commands, always `git diff` before adding; NO Co-Authored-By lines in commit messages (this overrides any attribution reminder); no DB migrations involved. Pre-existing uncommitted `v2/sim/src/sense.rs` change and `research/2026-10-24_mech-combat.md`: do not touch v2; the research file may be committed on its own as `docs`.
Agents: every Agent call sets name and model explicitly; all implementers sonnet; verifiers of type `claude` use chrome-devtools (read `prompts/chrome-devtools-mcp.md` first; max 6 tabs; shared real browser, do not touch accounts; if blocked stop and report).
Technical: zero third-party Rust crates (std only; std::thread::scope allowed); deterministic (same seed => byte-identical log; fixed dt, seeded splitmix RNG, no HashMap iteration in sim, threaded results collected in index order); viewer PixiJS ^8 + Vite + TS + vitest (copy v2/viewer toolchain). UI rules carried over: low cognitive load, no page scroll, tooltips on all controls, Lucide icons, light/dark theme, one accent colour; the landing at the base URL must never show a demo banner. v1/ and v2/ test suites must still pass at the end (run `cargo test` in v2/sim and `npm test` in v2/viewer once, before the final verifier).
Lessons from research/2026-10-23_learned-behaviour.md that v3 MUST NOT repeat: (a) holding a guard must cost energy every tick; (b) no context-free fitness bonus for a guard/block bit (there is no block bit at all in v3: defence is physical pose + collision); (c) draw must be strictly worse than any loss; (d) start close (5 m apart in a 14 m arena, not 41 tiles apart) and sensors see the whole arena (no FOV gaps); (e) penalise guarding with no live threat; (f) anti-stalemate bleed; (g) measure means over 3 seeds, not one run.

## Design (the spec implementers follow)
Units: metres, kg, seconds. Physics dt = 1/60 s. Net decides every 3 ticks (20 Hz), joint targets held between. Match max 900 ticks (15 s). Side view: x horizontal, y up, ground at y=0; each robot has a facing sign (+1/-1) flipped to face the opponent when grounded and not mid-swing (turning costs 0.25 s, i.e. cannot spin instantly). Robot height 4.0 m standing (arena 14 m wide, 6 m high view).
